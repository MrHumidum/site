## 1. ОПИСАНИЕ И ЦЕЛЬ ПРОЕКТА
**haramain.online** — маркетплейс для русскоязычных жителей и паломников Мекки и Медины. Площадка позволяет продавцам выставлять товары, а покупателям — заказывать их с доставкой строго в Мекке или Медине. Оплата производится ручным банковским переводом по реквизитам карт с подтверждением чека.

---

## 2. ТЕХНИЧЕСКИЙ СТЕК И ОКРУЖЕНИЕ
* **CMS / Движок:** OpenCart 2.3.0.2.4 (сборка opencart.pro).
* **Язык & Шаблоны:** PHP 8.x, шаблонизатор `.tpl` (используются короткие теги `<? ?>` и `<?= ?>`).
* **База данных:** MySQL (префикс таблиц `oc_`).
* **Фронтенд:** Bootstrap 3 + кастомная верстка (`css/style.css`, `media/media.css`), jQuery 1.12 / 2.1.
* **Иконки:** SVG-спрайт в `catalog/view/theme/default/template/common/footer.tpl`.
* **Модуль оформления заказа:** `checkout/custom` (`extension/module/custom/*`).
* **Система продавцов:** `system/library/cart/seller.php`, `catalog/controller/add/product.php`, таблицы `oc_seller*`, `oc_bonus`, `oc_vyvod`.

## 7. КОНТРАКТЫ БД (v1.1.0, применены миграцией `sql/v1.1.0_lead_db_setup.sql`)

### 7.1. Чек оплаты
* `oc_order.receipt_file` VARCHAR(255) DEFAULT NULL — относительный путь к загруженному чеку (jpg/png/pdf). Заполняет DEV_B (B3), читает админка (B4).

### 7.2. Валюта
* `oc_currency`: код `SAR`, `symbol_left` = '', `symbol_right` = ' риал', `decimal_place` = 2, `value` = 1.00000000, статус 1.
* `config_currency` = `SAR`, `config_currency_auto` = 0. Валюты GBP/EUR/UAH/RUB отключены (status = 0).
* Цены в `oc_product.price` трактуются как SAR (базовая валюта, курс 1).

### 7.3. Статусы заказов (`oc_order_status`, language_id = 1)
| id | Название | Смысл по ТЗ |
|---|---|---|
| 1 | В обработке | Processing (оплата подтверждена админом) |
| 2 | Оплачен | Legacy, для старых заказов, новыми потоками не используется |
| 3 | Отменен | Cancelled |
| 4 | Ожидает оплаты | Pending Payment — статус нового заказа (`config_order_status_id` = 4) |
| 5 | Проверка чека | Payment Verification — после загрузки чека покупателем |
* `config_processing_status` = ["1","2","4","5"], `config_complete_status` = ["1","2"].
* Поток: 4 → 5 (покупатель загрузил чек) → 1 (админ подтвердил) или 3 (админ отклонил).
* ⚠ Для DEV_B: `catalog/model/seller/seller.php` считает бонусы продавца по условию `order_status_id > 1`. С новыми статусами это условие обязано стать `order_status_id IN (1, 2)`.

### 7.5. Формат реквизитов карт (модуль «Перевод на карту»)
Реквизиты хранятся в существующей настройке модуля `bank_transfer_bank{language_id}` (Админка → Модули → Оплата → Перевод на карту, поле «Банковские реквизиты»). Новых полей БД не требуется.

Формат — одна карта в строке, три части через `|`:
```
Банк | Номер карты | Имя получателя
```
Пример:
```
Аль Раджхи | 4111 1111 1111 1111 | AHMAD AL FAHD
Альбилад | 5555 4444 3333 2222 | SALEH OMAR
```
* Номер карты копируется в буфер без пробелов (кнопка «Скопировать»).
* Строки без `|` игнорируются как карты — их можно использовать для примечаний, они выводятся только при отсутствии корректных карт.
* Пока поле пустое, покупатель видит сообщение «Реквизиты для оплаты пока не заданы».

### 7.6. Чек об оплате
* Файл чека: JPG, PNG или PDF, до 10 МБ, сохраняется в `system/storage/upload/` под именем `receipt_<order_id>_<token>.<ext>`; имя пишется в `oc_order.receipt_file`.
* Просмотр в админке — через контроллер `sale/order/receipt` (проверяет права `access sale/order`), прямая ссылка на файл не используется.
* Поток статусов: заказ создаётся в `4 Ожидает оплаты`, после нажатия «Я оплатил» переходит в `5 Проверка чека`; админ жмёт «Подтвердить оплату» (→ `1 В обработке`) или «Отклонить» (→ `3 Отменен`).
* Статус проверки можно переопределить настройкой `bank_transfer_verification_status_id`, по умолчанию 5.
